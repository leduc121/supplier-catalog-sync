Demo guide

Six short workflows that show the catalog’s safety rules using real persisted state.

Normal import

Run “Normal catalog” without an outage. Four products are created, one price changes, and A2 becomes a retained withdrawal tombstone.

Outage and resume

Choose “after batch 2”. The run stops incomplete at 2/3; Resume fetches only batch 3 and completes it.

Repeat the feed

Start “Normal catalog” again after completion. No duplicate product or change is created; four records are unchanged and two are stale.

Out-of-order records

Run “Repeated and out of order”. B1 remains withdrawn at revision 3 even though older active records arrive later.

Invalid records

Run “Invalid records”. Valid rows commit, while three validation errors and one revision conflict appear in Report.

Missing batch

Run “Missing final batch”. It remains incomplete at 2/3 on every Resume until the supplier delivers batch 3.

Process restart recovery

The browser demo exposes supplier outages only; it never terminates the shared server. To demonstrate a real application interruption, stop the server after a committed batch, start it again with the same DATA_DIR, and Resume. Automated tests also interrupt a separate process and reopen its JSON state.
